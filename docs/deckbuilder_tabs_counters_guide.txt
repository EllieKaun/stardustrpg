  ЧАСТЬ 0. ПРИНЯТЫЕ РЕШЕНИЯ
================================================================================

0.1. Сам Panel почти не трогаем — меняем, ЧТО в нём лежит.
  У Panel уже есть два вида вкладок:
    tabs     — горизонтальный ряд над панелью (сейчас там категории);
    sideTabs — вертикальная колонка слева внутри панели (сейчас там наборы).
  «Поменять местами» = положить наборы в tabs, а категории в sideTabs и
  поменять местами обработчики onTabClick / onSideTabClick. Вся навигация
  (мышь, стрелки, Q/E) уже написана и продолжит работать.

0.2. Первая категория — «ВСЕ». Она же открыта по умолчанию.
  buildCollectionSlots уже понимает category = undefined как «без фильтра».

0.3. Порядок категорий как на скриншоте: ВСЕ, МАГ, АТК, БАФФ, ЛЕЧ, ОСОБ.
  Подписи короткие — колонка узкая. Старые ключи deck.magic и т.д. не удаляем.

0.4. Считаем РАЗНЫЕ карты, а не копии и не редкости.
  «Собрано» = у игрока есть хотя бы одна копия этой карты любой редкости.
  Три одинаковых «Удара» — это 1, а не 3. Обычный и редкий «Удар» — тоже 1.
  (Вариант с редкостями — в 6.5.)

0.5. «Всего» = карты, которые в игре реально можно получить.
  Источники: все четыре списка наград zoneContent (rewardAlways,
  rewardNightOnly, rewardAfterBoss, rewardForestSet), магазин (shopCards) и
  награды квестов. Карты, которые есть только в реестре (bossClone врага,
  мультитаргеты, которые пока нигде не выдаются), в «всего» не входят —
  иначе игрок увидит «13/60» и никогда не соберёт.
  Ночные и «после босса» считаются сразу, а не по мере открытия: знаменатель
  не должен прыгать.

0.6. Что от чего зависит.
  Счётчик набора    — по всему набору, от категории не зависит.
  Счётчик категории — внутри ВЫБРАННОГО набора (ровно то, что видно в сетке).
  Ни один счётчик не зависит от деки: карта, положенная в деку, остаётся
  собранной. Поэтому пересчёт нужен только при открытии декбилдера и при
  смене набора, но не после перетаскивания карт.

0.7. Числитель никогда не больше знаменателя.
  Карты, которых нет в списке «можно получить» (например, после отладочного
  unlockAllCards), в «собрано» не попадают.

0.8. Наборы, которых у игрока ещё нет, по-прежнему скрыты (ownedCardSets).
  Если нужно показывать «ЛЕСНОЙ 0/5» до встречи с Фирой — 8.4.

================================================================================
  ЧАСТЬ 2. ПОДГОТОВКА: ДВЕ ФУНКЦИИ cardSetOf (УЖЕ СДЕЛАНО)
================================================================================

В ветке были две глобальные функции с одним именем cardSetOf: одна в
scrCardRegistry (принимает id), другая в scrCollectionDecks (принимает
структуру карты). У глобальных функций GML одно пространство имён, и с двумя
одинаковыми проект не запускался. Теперь имена разные:

  scrCardRegistry:    function cardSetById(cardId)  — по записи реестра
  scrCollectionDecks: function cardSetOfCard(card)  — по полю cardSet карты

Вызовы переименованы:
  scrEffectSystem (стр. 602)            -> cardSetById(cardId)
  buildCollectionSlots (стр. 256)       -> cardSetOfCard(card)
  ownedCardSets (стр. 316)              -> cardSetOfCard(card)

Правило: есть только id — cardSetById, карта уже построена — cardSetOfCard.
Дальше в гайде везде, где есть только id (счётчики, 8.4), используется
cardSetById.

2.1. Необязательно: ownedCardSets без постройки карт
  Сейчас ownedCardSets строит каждую карту коллекции через cardFromRef только
  ради набора. Через реестр быстрее:

    function ownedCardSets() {
        var sets = [CardSet.Base]
        var refs = getCollectionRefs()
        for (var refIndex = 0; refIndex < array_length(refs); refIndex++) {
            var set = cardSetById(refs[refIndex].id)
            if (!array_contains(sets, set)) { array_push(sets, set) }
        }
        array_sort(sets, true)
        return sets
    }

Проверка: открой декбилдер, во вкладке «ЛЕСНОЙ» только лесные карты, во
«ЗВЁЗДНЫЙ» — ни одной лесной. Лесное «случайное зелье» в бою работает как раньше.

Все правки — в конструкторе Panel (scrDeckBuilderDrawing). После этой части

3.1. Подпись вкладки
  У вкладки появляется необязательное поле counter (строка вида "3/12").
  Подпись = имя + счётчик. Добавь метод рядом с getTabWidths:

    static tabLabel = function(tab) {
        var counter = tab[$ "counter"]
        return (counter == undefined) ? tab.name : tab.name + " " + counter
    }

  tab[$ "counter"] — безопасное чтение: если поля нет, вернёт undefined, а не
  упадёт. Вкладки Ланы/Вив и альбом счётчика не имеют — у них всё как было.

3.2. Ширина верхних вкладок — getTabWidths
  Ширина считается по тексту, значит, должна учитывать счётчик. Было:

            var textScale = uiTextScale(tabs[tabIndex].name, tabH * 0.8, 1000000)
            var inset = (tabs[tabIndex][$ "textInset"] ?? 0) * tabH
            var textWidth = inset + string_width(tabs[tabIndex].name) * textScale + tabPadding

  стало:

            var label = tabLabel(tabs[tabIndex])
            var textScale = uiTextScale(label, tabH * 0.8, 1000000)
            var inset = (tabs[tabIndex][$ "textInset"] ?? 0) * tabH
            var textWidth = inset + string_width(label) * textScale + tabPadding * 2

  tabPadding * 2 — отступ с обеих сторон. У вкладок без спрайта (наборы) иначе
  текст упирается в край. Вкладкам со спрайтом это не мешает: у них ширина —
  max(ширина арта, ширина текста), и арт обычно шире.

3.3. Одна функция рисования «таблетки»
  Боковые вкладки уже рисуются скруглённым прямоугольником. Верхние вкладки без
  спрайта рисуются простым draw_rectangle — на скриншоте они тоже «таблетки».
  Чтобы не копировать код, вынеси рисование в метод:

    static drawPill = function(pillX, pillY, pillW, pillH, color, isActive) {
        var corner = 6 * uiScale
        draw_set_color(color)
        draw_set_alpha(isActive ? 1.0 : 0.55)
        draw_roundrect_ext(pillX, pillY, pillX + pillW, pillY + pillH, corner, corner, false)
        draw_set_alpha(1.0)
        if (isActive) {
            draw_set_color(c_white)
            draw_roundrect_ext(pillX, pillY, pillX + pillW, pillY + pillH, corner, corner, true)
        }
    }

            } else {

4.1. Функция вкладки категории
  Рядом с cardSetTab в scrCollectionDecks — по тому же образцу:

    function cardCategoryTab(category) {
        switch (category) {
            case CardCategory.Magic: return { name: loc("deck.magicShort"), color: #9944CC }
            case CardCategory.Attack: return { name: loc("deck.attackShort"), color: #CC4444 }
            case CardCategory.Buff: return { name: loc("deck.buffShort"), color: #44AACC }
            case CardCategory.Heal: return { name: loc("deck.healShort"), color: #44CC44 }
            case CardCategory.Special: return { name: loc("deck.specialShort"), color: c_white, textColor: c_black }
            default: return { name: loc("deck.all"), color: c_white, textColor: c_black }
        }

  «Все» — это category = undefined. Ни один case с undefined не совпадёт,
  сработает default. Цвета взяты из старых вкладок, кроме баффа — на скриншоте
  он голубой (было #CC44CC, почти как магия).

  Функция каждый раз возвращает НОВУЮ структуру. Это важно: в части 7 в неё
  будет дописываться counter, и общий объект на все вызовы перепутал бы
  счётчики.

6.2. Какие карты можно получить

    function collectibleCardIds() {
        var content = zoneContent()
        var ids = []

        appendRewardIds(ids, content.rewardNightOnly)
        appendRewardIds(ids, content.rewardAfterBoss)

        appendRewardIds(ids, content.questCards)

            appendRewardIds(ids, [content.shopCards[shopIndex].id])

        return ids
    }

6.3. Какие карты у игрока есть

    function ownedCardIds() {
        var ids = []
        var refs = getCollectionRefs()
        for (var refIndex = 0; refIndex < array_length(refs); refIndex++) {
            var cardRef = refs[refIndex]
            if (cardRef.count > 0 && !array_contains(ids, cardRef.id)) { array_push(ids, cardRef.id) }
        }
        return ids
    }

  В коллекции ключ — «id@редкость», поэтому одна карта разных редкостей —
  это несколько записей. array_contains склеивает их в один id (решение 0.4).
  Копии в деках тоже лежат в коллекции (дека хранит только ссылки), поэтому
  карта в деке считается собранной без отдельной проверки.

6.4. Сам счётчик

    function collectionProgress(category = undefined, cardSet = undefined) {
        var collectible = collectibleCardIds()
        var owned = ownedCardIds()
        var progress = { owned: 0, total: 0 }
        for (var idIndex = 0; idIndex < array_length(collectible); idIndex++) {
            var cardDefinition = global.cardRegistry[$ collectible[idIndex]]
            if (category != undefined && cardDefinition.category != category) { continue }
            if (cardSet != undefined && cardDefinition.cardSet != cardSet) { continue }
            progress.total++
            if (array_contains(owned, cardDefinition.id)) { progress.owned++ }
        }
        return progress
    }

    function progressText(progress) {
        return string(progress.owned) + "/" + string(progress.total)
    }

  cardFromRef было бы правильно, но медленно: каждая постройка — вызов
  фабрики, cardBalance и т.д.

  * refreshCategoryTabs вызывается внутри конфига collectionPanel: панели ещё
    нет, ошибка при создании объекта. Вызывай после new Panel(...).


Совет: части 2–5 — это полчаса и сразу видимый результат. Счётчики (6–7)
