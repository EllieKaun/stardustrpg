Итог после всех частей:
  - глобальное «время суток», которое плавно течёт (или переключается);
  - весь мир плавно тонируется от дневного к ночному (тёмно-синий вечер);
  - источники света (факелы, костры, свечение) вырезают тёплые круги в темноте,

(мировые координаты), а не в Draw GUI. Экранное затемнение переходов
(oTransition, application_surface) — отдельная штука, его не трогаем.

================================================================================
  ЧАСТЬ 1. ИДЕЯ «КАРТЫ СВЕТА» (LIGHTMAP)
================================================================================

Без шейдеров 2D-освещение делают через поверхность-карту света и режим
смешивания «умножение». Пошагово, что происходит каждый кадр:

  1. Берём поверхность размером с вид камеры (320x180) — lightSurface.
  2. Очищаем её в ЦВЕТ ОКРУЖАЮЩЕГО СВЕТА (ambient):
       день  — белый (c_white): умножение на белый ничего не меняет, сцена как есть;
       ночь  — тёмно-синий (напр. RGB 40,50,90): умножение затемнит и посинит сцену.
  3. На эту поверхность в местах источников света рисуем мягкие радиальные пятна
     ЦВЕТА СВЕТА (тёплый оранжевый факел) в режиме СЛОЖЕНИЯ (bm_add). Там, где
     факел — карта становится ярче и теплее.
  4. Рисуем lightSurface поверх всей сцены в режиме УМНОЖЕНИЯ. Пиксель экрана
     умножается на пиксель карты: тёмная синяя карта = ночь, светлый тёплый круг
     от факела = освещённое пятно.

Почему умножение: цвет_на_экране * цвет_карты. Умножение на белый (1,1,1) =
без изменений (день). На тёмный (0.15,0.2,0.35) = темно и синё (ночь). Плюс
локальная добавка света в карту делает круги вокруг факелов.

Плавность дня/ночи = просто плавно меняем цвет очистки карты (шаг 2) между
белым и ночным. Никаких скачков.


================================================================================
  ЧАСТЬ 2. СИСТЕМНЫЕ ФУНКЦИИ GML
================================================================================

2.1. Поверхности (surface) — оффскрин-картинка, на которой можно рисовать
  surface_create(w, h) — создать. Дорого, создаём один раз и переиспользуем.
  surface_exists(surf) — жива ли. Поверхности могут «умирать» при сворачивании
    окна/смене разрешения — ВСЕГДА проверяй surface_exists и пересоздавай.
  surface_set_target(surf) — направить всё дальнейшее рисование в surf.
  surface_reset_target() — вернуть рисование на экран. Обязательно парой к set.
  draw_clear_alpha(color, alpha) — залить всю поверхность цветом (с альфой).
  draw_surface(surf, x, y) — нарисовать поверхность в точке.
  surface_free(surf) — освободить (при пересоздании другого размера).

2.2. Режимы смешивания (blend) — как новый пиксель ложится на имеющийся
  gpu_set_blendmode(bm_normal)   — обычное наложение (по умолчанию).
  gpu_set_blendmode(bm_add)      — сложение: цвета складываются, картинка светлеет.
                                   Так рисуем пятна света на карту.
  gpu_set_blendmode_ext(bm_dest_colour, bm_zero) — УМНОЖЕНИЕ: результат =
                                   пиксель_экрана * пиксель_поверхности.
                                   Так накладываем готовую карту света на сцену.
  ПРАВИЛО: после любых махинаций с blend ВСЕГДА возвращай gpu_set_blendmode(bm_normal),
  иначе всё, что рисуется после, поедет.

2.3. Цвет и смешивание цветов
  make_color_rgb(r, g, b) — цвет из компонент 0..255.
  merge_color(c1, c2, amount) — смешать два цвета: amount=0 → c1, 1 → c2, 0.5 —
    поровну. Ключевой инструмент для плавного дня→ночи (лерп цвета).
  draw_sprite_ext(spr, sub, x, y, xs, ys, rot, colour, alpha) — спрайт с
    масштабом/цветом/прозрачностью. Свет = радиальный спрайт, colour = цвет света.

2.4. Плавность во времени
  lerp(a, b, t) — a + (b-a)*t. Плавно подтягивать значение к цели каждый кадр.
  clamp(v, lo, hi) — ограничить.
  smoothstep — плавная S-кривая. В GML нет, делается руками:
    function smoothstep(edge0, edge1, x) {
        var t = clamp((x - edge0) / (edge1 - edge0), 0, 1)
        return t * t * (3 - 2 * t)
    }
  Нужна, чтобы рассвет/закат были мягкими на границах, а не линейными.
  delta_time — микросекунды с прошлого кадра. Для времени суток, не зависящего
    от FPS: приращение = delta_time / 1000000 * скорость.

2.5. Аудио-фейд
  audio_sound_gain(soundId, targetGain, timeMs) — плавно за timeMs мс подвести
    громкость звука к targetGain. Это встроенный фейд, ничего в Step крутить
    не надо. audio_is_playing(soundId) — играет ли. audio_stop_sound(soundId).

2.6. Синусоида для мерцания
  sin(current_time / period) — плавные колебания в [-1..1]. current_time —
    миллисекунды с запуска. Так «дышит» яркость факела.


================================================================================
  ЧАСТЬ 3. ВРЕМЯ СУТОК (МОДЕЛЬ ДАННЫХ)
================================================================================

Одна глобальная величина — фаза суток. Держи в [0, 1): 0 — полночь, 0.25 —
рассвет, 0.5 — полдень, 0.75 — закат. Или проще: 0..1, 0 — глубокая ночь,
0.5 — полдень. Выбери и держись одного соглашения.

Заведи скрипт scrDayNight (Create проекта/контроллера инициализирует):

  Инициализация (например в oGameController Create):
    global.timeOfDay = 0.5          // старт в полдень
    global.timeSpeed = 1 / 120      // за сколько СЕКУНД реального времени
                                    // проходят сутки; 1/120 = сутки за 2 минуты
    global.timePaused = false       // ночь можно ставить и вручную

  Обновление (в Step контроллера мира):
    function updateTimeOfDay() {
        if (global.gamePaused || global.timePaused) { return }
        var deltaSeconds = delta_time / 1000000
        global.timeOfDay += deltaSeconds * global.timeSpeed
        global.timeOfDay -= floor(global.timeOfDay) // держим в [0,1)
    }

  «Насколько сейчас ночь» — 0 днём, 1 ночью, плавно на переходах:
    function nightAmount() {
        var t = global.timeOfDay
        // День примерно [0.25..0.75], ночь — остальное. Рассвет/закат — плавные
        // окна шириной ~0.1. Возвращаем 1 ночью, 0 днём.
        // TODO: через smoothstep сделать плавные закат (0.70->0.80) и
        //       рассвет (0.20->0.30). Подсказка:
        //   var dayFactor = smoothstep(0.20, 0.30, t) * (1 - smoothstep(0.70, 0.80, t))
        //   return 1 - dayFactor
    }

Совет: пока делаешь свет (части 4-5), временно замени течение времени на ручной
переключатель (клавиша), чтобы не ждать — например по нажатию менять
global.timeOfDay между 0.5 (день) и 0.0 (ночь). Так проверять быстрее.


================================================================================
  ЧАСТЬ 4. ТОНИРОВКА МИРА ДЕНЬ/НОЧЬ (без источников света)
================================================================================

Сначала простое: весь мир плавно темнеет ночью. Источники добавим в части 5 —
архитектуру сразу закладываем под них.

4.1. Объект oLighting
  Создай объект oLighting без спрайта. Один на комнату. Проще всего создать
  из oGameController Create:
    if (!instance_exists(oLighting)) { instance_create_depth(0, 0, -100000, oLighting) }
  Очень маленький depth (-100000) => рисуется ПОСЛЕ мира, т.е. ПОВЕРХ него.
  (В GM меньший depth = позже рисуется = выше.) Свет должен быть выше мира,
  но ниже интерфейса — GUI (Draw_64) в любом случае поверх Draw, так что ок.

  События oLighting: Create, Draw (обычный Draw — событие Draw, НЕ Draw GUI).

4.2. Create oLighting
  lightSurface = -1
  // Цвета окружения
  dayColor = c_white                       // днём умножение на белый = без изменений
  nightColor = make_color_rgb(45, 55, 95)  // тёмно-синий вечер (подбери на глаз)

4.3. Draw oLighting (мировые координаты)
  var cam = view_camera[0]
  var viewX = camera_get_view_x(cam)
  var viewY = camera_get_view_y(cam)
  var viewW = camera_get_view_width(cam)
  var viewH = camera_get_view_height(cam)

  // 1) поверхность размером с вид (пересоздаём при нужде)
  if (!surface_exists(lightSurface)) { lightSurface = surface_create(viewW, viewH) }
  // (если меняешь разрешение вида — добавь проверку размеров и surface_free)

  // 2) цвет окружения по времени суток
  var ambient = merge_color(dayColor, nightColor, nightAmount())

  surface_set_target(lightSurface)
  draw_clear_alpha(ambient, 1)      // залить карту светом окружения
  // (в части 5 здесь же нарисуем пятна факелов в bm_add)
  surface_reset_target()

  // 3) наложить карту на сцену УМНОЖЕНИЕМ, выровняв по камере
  gpu_set_blendmode_ext(bm_dest_colour, bm_zero)
  draw_surface(lightSurface, viewX, viewY)
  gpu_set_blendmode(bm_normal)      // ОБЯЗАТЕЛЬНО вернуть

  Почему draw_surface(lightSurface, viewX, viewY): поверхность размером с вид,
  а рисуем её в мировых координатах на месте камеры — она ложится ровно на
  видимую область.

Проверка: переключай nightAmount() между 0 и 1 (ручной клавишей из части 3).
День — без изменений, ночь — мир тёмно-синий. Переход плавный, если менять
timeOfDay плавно.

4.4. Что НЕ попадёт под тонировку
  Тонируется всё, что нарисовано ДО oLighting (мир, объекты, тайлы). Интерфейс
  (панели героев, карты — они в Draw GUI) не тонируется — и хорошо, UI должен
  оставаться читаемым. Если хочешь, чтобы что-то в мире светилось и ночью
  (окна домов) — это источник света (часть 5).


================================================================================
  ЧАСТЬ 5. ИСТОЧНИКИ СВЕТА (ФАКЕЛ, КОСТЁР)
================================================================================

Свет — мягкое радиальное пятно, добавляемое в карту (bm_add) до наложения на
сцену. Источники регистрируются у oLighting, как в драг-н-дропе цели у менеджера.

5.1. Спрайт свечения
  Нужен sprLight — белый мягкий радиальный градиент (яркий центр → прозрачные
  края), квадрат ~128x128, origin по центру. Нарисуй в редакторе спрайтов
  (радиальная кисть) или сгенерируй. Белый — потому что цвет зададим при рисовании
  через colour у draw_sprite_ext (умножит белый на нужный цвет).

5.2. Реестр источников (в oLighting Create)
  lights = []   // список источников
  addLight = function(cfg) { array_push(lights, cfg); return cfg }
  removeLight = function(light) {
      // TODO: найти и удалить из lights (array_delete по индексу)
  }
  Источник — структура:
    {
      x, y,                 // мировые координаты центра
      radius,               // радиус в пикселях (масштаб sprLight)
      color,                // цвет света (тёплый оранжевый факел ~ 255,170,80)
      intensity,            // 0..1 базовая яркость
      flicker               // амплитуда мерцания 0..~0.15 (0 = ровный)
    }

5.3. Кто создаёт источник
  Объект-факел (oTorch) в Create:
    myLight = oLighting.addLight({ x: x, y: y, radius: 64,
        color: make_color_rgb(255, 170, 80), intensity: 1, flicker: 0.08 })
  В Step (если факел движется — например в руке героя):
    myLight.x = x; myLight.y = y
  В Destroy/CleanUp:
    if (instance_exists(oLighting)) { oLighting.removeLight(myLight) }
  ВАЖНО: убирать источник при удалении объекта, иначе «повиснет» призрачный
  свет и/или обращение к мёртвой структуре.

5.4. Рисование пятен (в Draw oLighting, ВНУТРИ surface_set_target, после clear)
  Между draw_clear_alpha(...) и surface_reset_target() добавь:

    gpu_set_blendmode(bm_add)
    for (var lightIndex = 0; lightIndex < array_length(lights); lightIndex++) {
        var light = lights[lightIndex]
        // координаты света ОТНОСИТЕЛЬНО поверхности = мир минус угол вида
        var localX = light.x - viewX
        var localY = light.y - viewY
        // мерцание: чуть колышем яркость
        var flick = 1
        // TODO: if (light.flicker > 0) flick = 1 - light.flicker * (0.5 + 0.5*sin(current_time/90 + lightIndex))
        var scaleXY = (light.radius * 2) / sprite_get_width(sprLight)
        var alpha = clamp(light.intensity * flick, 0, 1)
        draw_sprite_ext(sprLight, 0, localX, localY, scaleXY, scaleXY, 0, light.color, alpha)
    }
    gpu_set_blendmode(bm_normal)

  Порядок в Draw становится: очистить карту в ambient → сложить пятна света
  (bm_add) → surface_reset_target → наложить карту умножением на сцену.

5.5. Тонкость: свет виден и днём?
  Днём ambient = белый (карта уже яркая), добавка света почти незаметна — это
  правильно, факел днём не светит. Ночью карта тёмная, и добавленные пятна
  реально высветляют. Если хочешь, чтобы факел чуть заметен и днём — множь его
  intensity на nightAmount() (днём гаснет, ночью разгорается):
    var alpha = clamp(light.intensity * flick * max(0.15, nightAmount()), 0, 1)

Проверка: поставь oTorch в комнату, включи ночь — вокруг факела тёплый круг,
центр ярче, края мягко тонут в синей темноте. Подвигай героя с факелом —
пятно едет за ним без рывков.


================================================================================
  ЧАСТЬ 6. МУЗЫКА И ЭМБИЕНТ ПО ВРЕМЕНИ СУТОК (ПЛАВНО)
================================================================================

Сейчас playMusic жёстко обрывает и запускает трек. Для плавной смены день↔ночь
нужен кроссфейд. У тебя есть audio_sound_gain(sound, gain, timeMs) — встроенный
фейд, идеально.

6.1. Кроссфейд-хелпер (в scrAudio.gml)
  function crossfadeMusic(track, fadeMs = 1500) {
      if (!variable_global_exists("currentMusic")) { global.currentMusic = noone }
      if (track < 0) { return }
      if (global.currentMusic == track && audio_is_playing(track)) { return } // уже играет
      // старый трек: увести в 0 и остановить
      if (global.currentMusic >= 0 && audio_is_playing(global.currentMusic)) {
          audio_sound_gain(global.currentMusic, 0, fadeMs)
          // TODO: остановить старый через fadeMs. Без таймера можно просто
          //       не останавливать вручную, а перезаписать currentMusic и
          //       остановить его на СЛЕДУЮЩЕЙ смене. Но чище — отложенный стоп:
          //       например через alarm или через хранение { id, stopAt }.
      }
      // новый трек: стартуем с 0 и поднимаем до целевой
      var sound = audio_play_sound(track, 10, true)
      audio_sound_gain(sound, 0, 0)
      audio_sound_gain(sound, global.volMusic, fadeMs)
      global.currentMusic = sound  // ВНИМАНИЕ: тут id ЗВУКА, не ассета (см. ниже)
  }

  ВАЖНО про id: в текущем playMusic global.currentMusic хранит то ASSET id
  (track), то sound id — это уже слегка мешано. Для кроссфейда надёжнее хранить
  ИМЕННО id проигрываемого звука (возврат audio_play_sound). Тогда сравнение
  «тот же трек» делай по отдельно хранимому global.currentMusicAsset:
    global.currentMusicAsset = track
    global.currentMusic = sound
  и в проверке «уже играет» сравнивай global.currentMusicAsset == track.
  Приведи playMusic/crossfade к одному соглашению, чтобы не путать asset и sound.

6.2. Отложенная остановка старого трека
  Проблема: если просто не останавливать старый, он продолжит играть под новым.
  Варианты:
   а) держать очередь «затухающих» звуков { id, framesLeft } и в Step аудио-
      контроллера уменьшать счётчик, по нулю — audio_stop_sound. Надёжно.
   б) на старый повесить alarm через объект-аудио-менеджер.
  Проще всего (а): небольшой список global.fadingOut, обновляемый в Step.

6.3. Выбор трека по времени суток (в Step контроллера мира)
  С гистерезисом, чтобы на границе день/ночь музыка не «дёргалась» туда-сюда:

    function updateDayNightMusic() {
        var night = nightAmount()
        if (!variable_global_exists("musicIsNight")) { global.musicIsNight = (night > 0.5) }
        // гистерезис: переключаемся в ночь при >0.6, обратно в день при <0.4
        if (!global.musicIsNight && night > 0.6) {
            global.musicIsNight = true
            crossfadeMusic(asset_get_index("ForestNightMusic"))
        } else if (global.musicIsNight && night < 0.4) {
            global.musicIsNight = false
            crossfadeMusic(asset_get_index("ForestDayMusic"))
        }
    }

  Эмбиент (ForestAmbience) можно оставить общим, или так же держать дневной/
  ночной вариант. Если ночного эмбиента нет — можно ночью приглушать общий:
  audio_sound_gain(global.currentAmbient, global.volSounds * (1 - 0.5*night), 500).

6.4. Где вызывать
  В Room Start (oGameController Other_4) сейчас жёстко ставится ForestDayMusic.
  Замени на выбор по времени суток: посчитать nightAmount() и запустить нужный
  трек СРАЗУ (без фейда, fadeMs=0 при входе в комнату — плавность нужна при
  СМЕНЕ суток, а не при входе). А updateDayNightMusic() зови каждый Step.
  Не забудь: на паузе и в модалках время не течёт (часть 3), значит и музыка
  не переключается — это правильно.

Проверка: ускорь global.timeSpeed (сутки за 20 сек), смотри переход заката —
картинка синеет, музыка плавно перетекает в ночную, на рассвете обратно.


================================================================================
  ЧАСТЬ 7. МЕРЦАНИЕ, ДВИЖУЩИЕСЯ ИСТОЧНИКИ, ШЛИФОВКА
================================================================================

7.1. Мерцание факела: разная фаза у каждого
  В формуле мерцания добавляй индекс/уникальный сдвиг, чтобы факелы не пульсировали
  синхронно: sin(current_time / 90 + light.phase), где light.phase — случайная
  фаза, заданная при addLight (random(6.28)).

7.2. Лёгкое дрожание позиции/радиуса
  Костёр «дышит»: radius колышем на пару пикселей тем же sin. Не переусердствуй.

7.3. Луна/звёзды ночью
  Ночью поверх мира (в oLighting, ПОСЛЕ наложения карты) можно бросить очень
  слабый синий оверлей или спрайты звёзд с alpha = nightAmount() * 0.2.

7.4. Производительность
  Одна поверхность на весь вид — дёшево. Десятки источников — тоже (это просто
  спрайты). НЕ создавай поверхность каждый кадр (только при !surface_exists).
  Радиальный спрайт держи небольшим (128px) и масштабируй — не рисуй огромные.

7.5. Świатło в бою?
  Бой — отдельная комната (BattleRoom) со своим фоном и своим рендером (Battle
  рисует через setCrispGui и т.д.). Если ночной бой нужен — там свой oLighting
  или передавай nightAmount() в затемнение фона боя. По умолчанию свет только
  в мире; в бой время суток можно просто «заморозить» на входе.

7.6. Плавность на входе в комнату
  timeOfDay — глобальная и persistent, поэтому при переходах между мировыми
  комнатами время не сбрасывается. Свет и музыка подхватят текущую фазу. Проверь,
  что oLighting создаётся в каждой мировой комнате (через oGameController Create).


================================================================================
  ЧАСТЬ 8. ПОРЯДОК ВНЕДРЕНИЯ И ЧЕК-ЛИСТ
================================================================================

Делай по частям, проверяя каждую:
  1. Часть 3 — время суток + ручной переключатель день/ночь (клавиша).
  2. Часть 4 — oLighting и тонировка (умножение карты). Убедись, что день не
     меняет картинку, ночь синит, переход плавный.
  3. Часть 5 — sprLight, реестр источников, oTorch, пятна в bm_add.
  4. Часть 6 — crossfadeMusic + выбор трека с гистерезисом.
  5. Часть 7 — мерцание, движущийся факел у героя, шлифовка.
  6. Убрать временный ручной переключатель, включить течение времени.

Чек-лист:
  [ ] День: мир выглядит как раньше (умножение на белый — без изменений).
  [ ] Ночь: мир тёмно-синий, плавный переход на закате/рассвете.
  [ ] Факел: тёплый круг, мягкие края, центр ярче.
  [ ] Факел на герое едет за ним без рывков.
  [ ] Несколько факелов мерцают вразнобой, не синхронно.
  [ ] Музыка плавно перетекает день↔ночь, без наложения двух треков.
  [ ] На границе суток музыка не дёргается (гистерезис работает).
  [ ] Пауза/модалки: время, свет-обновление и смена музыки замирают.
  [ ] Смена размера окна / фуллскрин — поверхность пересоздаётся, без чёрного
      экрана (проверка surface_exists).
  [ ] Переход между комнатами мира — время и музыка не сбрасываются.
  [ ] Удаление факела (объекта) убирает его свет (removeLight в Destroy).


================================================================================
  ЧАСТЬ 9. ЧАСТЫЕ ОШИБКИ
================================================================================
  * Забыл вернуть gpu_set_blendmode(bm_normal) — весь последующий рендер (в т.ч.
    UI) поедет: всё складывается/умножается.
  * Рисуешь свет в Draw GUI вместо Draw — он в экранных координатах, не совпадёт
    с миром и не будет тонировать сцену правильно. Свет — мировой Draw.
  * Поверхность не выровнена по камере: draw_surface должен идти в (viewX, viewY),
    а координаты источников — минус (viewX, viewY). Иначе свет «уезжает».
  * Поверхность пересоздаётся каждый кадр (нет проверки surface_exists) — тормоза
    и мерцание. Создавай один раз, пересоздавай только если пропала/сменился размер.
  * Не проверил surface_exists после сворачивания окна — чёрный экран/краш.
  * global.currentMusic мешает asset id и sound id — кроссфейд сравнивает не то.
    Держи отдельно currentMusicAsset (что играет) и currentMusic (id звука).
  * Старый трек не останавливается после фейда — два трека играют вместе.
    Нужен отложенный стоп (часть 6.2).
  * Время идёт на паузе — ночь наступает, пока игрок в меню. Гасить по
    global.gamePaused / global.uiModal.
  * Свет не убрали при удалении объекта — «призрачное» пятно или обращение к
    мёртвой структуре в списке lights.
  * Тонируется UI: значит рисуешь свет в GUI или UI попал в мировой Draw. UI
    должен рисоваться ПОСЛЕ света (он и так в Draw GUI — не трогай).


Совет: начни с частей 3-4 (время + тонировка). Как только мир умеет плавно
синеть по одной глобальной величине — самое сложное позади, а факелы и музыка
навешиваются поверх быстро и независимо.
