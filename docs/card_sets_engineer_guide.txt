================================================================================
  ЧАСТЬ 0. ПРИНЯТЫЕ РЕШЕНИЯ
================================================================================

Решения из вики — как есть. Решения, которых в вики нет, помечены
«(предложение)»: их можно поменять, код от этого почти не меняется.

0.1. Детали получает тот, кто сыграл карту (вики).
  Деталь — эффект «на розыгрыш», он срабатывает у кастера, на кого бы ни
  была направлена карта.

0.2. Детали — состояние боя (предложение).
  В начале каждого боя 0, в сохранение не идут. Так же, как ингредиенты:
  боец создаётся заново на каждый бой.

0.3. Потолок запаса — 9 деталей (предложение).
  Торпеде нужно 5, значит, хватит с запасом. 9 — одна цифра на значке.
  Лишняя деталь сверх потолка просто теряется. Макрос PARTS_MAX.

0.4. Карта «требует N деталей» тратит их И стоит обычную цену (предложение).
  Вики: «повышенная стоимость будет необходимым ограничителем», детали —
  отдельное требование. Если решите, что Катапульта и Торпеда стоят ТОЛЬКО
  детали — в фабрике поставить card.costValueCached = 0 (как у Сумки
  припасов).

0.5. +20% к цене — всем инженерным картам (вики), округление вверх
  (предложение). Карте с ценой 1 это даёт 2 — если слишком дорого, замени
  ceil на round.

0.6. Карты требующие детали деталей НЕ дают (вики: у них нет «+1 деталь»).

0.7. «Случайному врагу» — случайный ЖИВОЙ враг в момент розыгрыша,
  игрок цель не выбирает. Катапульта и Торпеда выбирают цель заново на КАЖДЫЙ
  удар: если первый удар добил врага, следующие летят в живых (предложение —
  иначе часть ударов уходит «в труп»).

0.8. «Случайному персонажу» у Ремкомплекта и Батарейки — случайный живой
  союзник, включая самого кастера (предложение).

0.9. Броня: держится до первой атаки по персонажу или до конца N ходов, что
  раньше (предложение). Вечная броня, которая ждёт удара весь бой, слишком
  сильна в связке с провокацией. N зависит от редкости.
  Блокирует любую ПРЯМУЮ атаку (физ., маг., чистую). Урон по времени (яд,
  кровотечение, ожог) — не атака, не блокирует.

0.10. Набор доступен всем героям, врагам не даётся (как лесной).

0.11. Редкость: карты 2–12 зависят от редкости, Шестерня — нет (её базовая
  карта drawCard уникальная, и «взять 1 карту» нечем усиливать).

0.12. Где выпадает — не решено в вики. В гайде список rewardEngineerSet и
  два варианта подключения (9.5). Выбери сам.

    function randomAliveFrom(units) {
        var alive = []

================================================================================
  ЧАСТЬ 6. НОВЫЕ ЭФФЕКТЫ
================================================================================

Каждый новый вид эффекта — четыре места (как GainIngredient):
  значение в EffectTypes (в конец) -> case в effectKindFromType -> запись в
  initEffectRegistry -> функция-конструктор.

6.1. «Получить детали»

  EffectTypes: GainParts. effectKindFromType:

        case EffectTypes.GainParts: return "GainParts"

  Реестр:

    variable_struct_set(effectsRepository, "GainParts", {
        onPlay: function(effect, caster, targets) { partsAdd(caster, effect.value) }
    })

  Конструктор:

    function GainPartsEffect(count = 1) {
        return { type: EffectTypes.GainParts, value: count, timing: Timing.OnActions }
    }

6.2. «Серия ударов по случайным врагам» (Катапульта, Торпеда)

  EffectTypes: RandomHits. effectKindFromType:

        case EffectTypes.RandomHits: return "RandomHits"

  Реестр:

    variable_struct_set(effectsRepository, "RandomHits", {
        onPlay: function(effect, caster, targets) {
            var foes = caster.isEnemy ? Battle.heroes : Battle.enemies
            repeat (effect.hits) {
                var foe = randomAliveFrom(foes)
                if (foe == noone) { return }
                executeDamageEffect(DamageEffect(effect.damageType, effect.value), caster, foe)
            }
        }
    })

  Конструктор:

    function RandomHitsEffect(hits, value, damageType = DamageTypes.True) {
        return { type: EffectTypes.RandomHits, hits: hits, value: value, damageType: damageType, timing: Timing.OnActions }
    }

  Цель — заново на каждый удар (решение 0.7). Каждый удар — обычный
  executeDamageEffect, поэтому броня, Deflect, всплывающие цифры работают сами.
  Battle.enemies — потому что функция в реестре не знает, в каком она
  экземпляре; Battle в бою один.

6.3. Броня

  EffectTypes: Armor. StatusNames: Armor (оба в конец). effectKindFromType:

        case EffectTypes.Armor: return "Armor"

  Реестр (иконка статуса; пока нет спрайта — тот же, что у Deflect):

    variable_struct_set(effectsRepository, "Armor", { icon: stunned })

  statusNameIcon и weaknessIcon (scrEffectSystem) — добавить case для
  StatusNames.Armor, иначе у статуса не будет иконки в «Инфо».

  Конструктор:

    function ArmorEffect(duration, sprite = buffEffect, sound = MagicBuff) {
        return {
            type: EffectTypes.Armor, statusName: StatusNames.Armor,
            duration: duration, timing: Timing.Overtime,
            sprite: sprite, sound: sound
        }
    }

  Overtime — как у Deflect: статус висит duration ходов владельца и сам
  снимается (решение 0.9).

  Снять броню целиком (а не уменьшить длительность на 1, как делает
  reduceOrRemoveEffectType) — scrCombat:

    function armorConsume(target) {
        var effects = target.effects
        for (var effectIndex = 0; effectIndex < array_length(effects); effectIndex++) {
            if (effects[effectIndex].type == EffectTypes.Armor) {
                array_delete(effects, effectIndex, 1)
                return true
            }
        }
        return false
    }

  Не используй для этого executeRemoveStatus: он читает .statusName у КАЖДОГО
  эффекта, а у баффов этого поля нет — упадёт, если на цели висит бафф.

  Срабатывание — executeDamageEffect (scrCombat), два места.

  а) Физ./маг. урон — сразу после строки damage = mitigateDamage(...) и ДО
     проверки Deflect (стр. 214):

    if (armorConsume(targets)) {
        targets.showEffectNotification(effect, EffectVisualizerType.AnimationEnd, 1)
        return
    }

  б) Чистый урон — в ветке DamageTypes.True (стр. 166–179). Там цели бывают
     массивом и одиночкой. Перед каждым targets[i].applyDamage(...) и
     targets.applyDamage(...) — та же проверка, например для одиночки:

        } else if (!targets.isKO()) {
            if (!armorConsume(targets)) { targets.applyDamage(trueDamamge) }
            targets.showEffectNotification(effect, EffectVisualizerType.AnimationEnd, 1)
        }

  Броня раньше Deflect: если на цели и то, и другое, тратится броня, урон 0,
  отражения нет. Урон по времени идёт через другой путь (хук onEndOfTurn у
  "Damage") — броню не трогает, как и решено в 0.9.

Проверка: временной картой повесь броню на героя, дай врагу ударить — 0
урона, статус пропал; второй удар — полный. Броня без ударов — через N ходов

================================================================================
  ЧАСТЬ 7. КАРТЫ ИЗ БАЗОВЫХ (1–7, 9, 10)
================================================================================

Новый скрипт scrCardFactoryEngineer (создай в IDE).

7.1. Общий помощник

    function engineerFromBase(baseId, rarity, name, target, gainsPart = true) {
        var card = cardBuild(baseId, rarity)
        card.name = name
        card.cardSet = CardSet.Engineer
        card.target = target
        card.costValueCached = ceil(card.costValueCached * ENGINEER_COST_MULT)
        if (gainsPart) { array_push(card.effects, GainPartsEffect(1)) }
        return card
    }

  Почему так, а не «скопировать фабрику и поменять»:
  - базовая карта строится своей фабрикой — числа, иконки, звуки, шансы
    статусов, редкость берутся оттуда. Поменяешь баланс «Удара» — поменяется
    и Гаечный ключ;
  - цена считается в конструкторе Card по эффектам. На этот момент «+1 деталь»
    ещё нет, поэтому цена остаётся ценой одиночной атаки (см. ловушку
    computeCardCost в части 1). Потом ×1.2;
  - card.name — новое: по имени строится ключ кэша текста карты
    (cardFaceLayout). С именем базовой карты Гаечный ключ показывал бы текст
    «Удара»;

Чек-лист:
  [ ] Старые карты и бои работают как раньше.
  [ ] В декбилдере вкладка «ИНЖЕНЕРНЫЙ», у карт свой фон.
  [ ] Цена инженерных на 20% выше базовых (сравни Гаечный ключ и Удар).
  [ ] Цена Гаечного ключа — как у одиночной атаки ×1.2, не как у групповой.
  [ ] Каждая карта 1–7, 9, 10 даёт кастеру +1 деталь; детали не больше 9.
  [ ] Атаки бьют случайного живого врага без выбора; лечение и мана —
      случайному живому союзнику.
  [ ] Молоток оглушает, пила — кровотечение, ключ — шок, плоскогубцы — поджог
      (с базовыми шансами).
  [ ] Броня, Катапульта, Торпеда не играются без деталей и тратят их.
  [ ] Катапульта/Торпеда: удары после смерти цели уходят в живых; все враги
      мертвы — оставшиеся удары не тратятся впустую с ошибкой.
  [ ] Броня: первая атака — 0 урона и статус снят; яд/кровотечение проходят;
      без атак — сама исчезла через N ходов.
  [ ] В новом бою деталей 0.
  [ ] Значок деталей над бойцом, требование на карте, неиграбельные затемнены.
  [ ] Враги инженерные карты не играют.
  [ ] Тексты RU/EN, новые enum-значения в конце.
  [ ] Карты выпадают так, как решено в 9.5.

Частые ошибки:
  * GainPartsEffect добавлен в массив эффектов ДО new Card — физические карты
    стоят как групповые (computeCardCost смотрит на число эффектов).
  * Не изменено card.name — на Гаечном ключе текст «Удара» из кэша
    cardFaceLayout.
  * Новая цель добавлена в enum, но не в CharacterPlay — карта на Enter
    ничего не делает.
  * Требование деталей стоит после if (caster.isEnemy) в checkIfCanPlayCard —
    у героев работает, но порядок хрупкий; ставь перед.
  * Детали списываются в шаге 1, а эффект «получить» — в шаге 4: при будущих
    картах «потратить и получить» порядок путается. Всё в шаге 4.
  * Броня снимается через reduceOrRemoveEffectType — уменьшается длительность
    на 1, а не снимается: блокирует несколько атак подряд.
  * Броня снимается через executeRemoveStatus — падение на эффекте без
    statusName (любой бафф).
  * Броня не проверена в ветке чистого урона — Катапульта врага (если когда-то
    будет) пробивает броню.
  * У Катапульты цель RandomEnemy — анимация на одном враге, удары по другим.
  * Значение enum вставлено в середину — сдвигаются сохранённые номера.
  * Инженерные карты не исключены из ИИ — враг пытается сыграть RandomEnemy,
    ИИ не знает такой цели.


Совет: начни с шагов 1–4. Девять карт «из базовых» — это полдня, и набор уже
играется: случайные цели и детали видны сразу. Броня, Катапульта и Торпеда —
отдельный заход, когда детали копятся и видны над бойцом.
