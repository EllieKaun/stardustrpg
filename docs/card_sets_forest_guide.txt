Как и прошлые гайды — маршрут со скелетами и TODO. Это самая большая фича из
всех, поэтому порядок важен: сначала общие «кирпичи», потом простые карты,
в конце — «Пустая колба». Делай по частям, после каждой проверяй в игре.

Что получится:
  - понятие «набор карт»: карта знает, к какому набору относится;
  - у бойца в бою запас ингредиентов (цветок, гриб, листочек), максимум два;
  - обычные карты тратят верхний ингредиент и становятся сильнее;
  - четыре лесные карты: Сумка с припасами, Зелье провокации, Сбор припасов,
    Пустая колба (семь вариантов действия);
  - новые механики: провокация, яд, чистый урон, избыточное здоровье.

================================================================================
  ЧАСТЬ 0. ПРИНЯТЫЕ РЕШЕНИЯ
================================================================================

Эти решения уже приняты. Весь гайд дальше написан под них.

0.1. Набор «для Фиры» по теме, но доступен всем.
  Лесные карты лежат в общей коллекции, их могут класть в колоду Лана и Вив.
  У Фиры они зашиты в её фиксированную колоду (foxFixedDeck в
  scrStarriorsInitializer). Редактируемую колоду Фире сейчас НЕ делаем: это
  отдельная большая задача (enum Characters, сохранение decks, третья вкладка
  декбилдера).

0.2. Обычная карта тратит верхний ингредиент, только если он ей подходит.
  Не подходит — не трогает, ингредиент остаётся в запасе.

0.3. Запас полон (два) и пришёл третий — он вытесняет самый старый.

0.4. Колба тратит ВСЕ ингредиенты, что есть (ноль, один или два).

0.5. Два одинаковых ингредиента — та же форма колбы, но усиленная.
  «Цветок и цветок» = форма «только цветок» с количеством 2. То же для гриба
  и листочка.

0.6. Провокация заставляет врагов бить одну цель.
  Действует только на одиночные атаки. Удары по всей группе идут как обычно.

0.7. Ингредиент за провокацию выдаётся в конце каждого своего хода, пока
  статус висит.

0.8. Избыточное здоровье — отдельный запас «щита» поверх здоровья.
  Урон сначала съедает щит. Щит держится до конца боя (сам не сгорает).

0.9. Все карты наборов зависят от редкости, кроме уникальных.
  Обычная лесная карта: при регистрации canVaryRarity = true, числа — в
  cardBalance() (scrBalance) массивами по редкости, как у остальных карт.
  Уникальная: canVaryRarity = false, числа фиксированные.
  В лесном наборе уникальных карт пока нет: все четыре карты зависят от
  редкости и регистрируются с canVaryRarity = true.

0.10. Сумка с припасами тратит всю энергию — это и есть её цена.

0.11. Сбор припасов можно сыграть с пустой рукой: терять нечего, ингредиент
  всё равно выдаётся.


================================================================================
  ЧАСТЬ 1. КАРТА КОДА
================================================================================

Как добавить карту — пять мест (подробно в new_cards_guide.txt):
  id в cardIdsInit -> фабрика -> registerCard -> тексты -> пул наград/магазин.

Розыгрыш карты — scripts/scrCards, cardPlaySequence(card, caster, targets):
  шаг 1: applyCost, removeCardFromHand
  шаг 2: анимация кастера
  шаг 3: анимация эффектов
  шаг 4: для каждого эффекта по effect.timing:
           Instant   -> executeEffect  (хук onInstant)
           EndOfTurn -> effectApplyStatus (вешает статус, тикает в конце хода)
           Overtime  -> effectApplyStatus (пассивный статус с длительностью)
           OnActions -> runOnPlay (хук onPlay)
         затем caster.energy -= card.energy
  шаг 6: afterPlayChecks (конец хода или ещё одна карта, если осталась энергия)
  Данные в шаги передаются через ctx (ctx.card, ctx.caster, ctx.targets).

Эффекты — scripts/scrEffectSystem:
  initEffectRegistry: для каждого вида эффекта структура с хуками
    onInstant(effect, caster, targets), onPlay(...), onEndOfTurn(effect, character),
    onApply(effect, caster, target), icon / iconFor.
  Новый вид эффекта = значение в EffectTypes + case в effectKindFromType +
    запись в реестре + функция-конструктор (как BuffEffect).

Выбор цели игроком — scripts/scrBattleInitializer, шаг состояния CharacterPlay:
  по currentCard.target: SingleEnemyTarget -> выбор врага, SingleAllyTarget ->
  выбор союзника, AllEnemies/AllAllies/Self -> карта играется сразу.
  ВАЖНО: target — поле карты, задаётся при создании. Для колбы это проблема
  (часть 8).

Выбор цели врагом — objects/Battle/Alarm_0.gml + enemyResolveTarget
  (scripts/scrBattleFlow). У функции уже есть параметр preferFoe: «если задан,
  бей его». Это готовая точка для провокации.
  Куклы — runPuppetTurn (scripts/sprPuppetManagement).

Урон — executeDamageEffect -> mitigateDamage (защита, слабости) -> applyDamage.
Урон по времени — хук onEndOfTurn у "Damage" (тоже через mitigateDamage).
Лечение — executeHealing -> applyHeal (обрезает по maxHp).
Статусы — массив character.effects; длительность уменьшает updateOvertime
  (для Overtime) и executeEndOfTurn (для EndOfTurn) в конце хода владельца.
Рука — character.getCardsInHand(), removeCardFromHand(caster, card).
Энергия — character.energy / maxEnergy.


================================================================================
  ЧАСТЬ 2. НАБОР КАК ДАННЫЕ
================================================================================

2.1. Enum наборов (scrBattleEnums, в конец)
    enum CardSet { Base, Forest }
  Base — все существующие карты. Новые наборы добавляются в конец.

2.2. Поле у карты
  В конструкторе Card (scripts/scrCards): self.cardSet = CardSet.Base
  В фабриках лесных карт после создания: card.cardSet = CardSet.Forest
  (как с handAuras — не добавляй параметр в длинный конструктор).

2.3. Реестр
  Для фильтров и наград удобно знать набор без создания карты. В registerCard
  (scripts/scrCardRegistry) можно добавить необязательный параметр набора и
  хранить его в записи реестра. Тогда появится функция
    function cardSetOf(cardId) { ... }   // по записи реестра
  Если не хочешь трогать реестр — создавай карту через cardFromRef и читай
  cardSet, но это медленнее.

2.4. Где набор виден игроку
  - на карте: значок набора в углу (рисуется в drawCardFace, если cardSet != Base);
  - в декбилдере: вкладок пять и они по категориям; отдельную вкладку набора
    заводить дорого. Достаточно значка на карте и сортировки «карты набора рядом»;
  - в альбоме: то же.

2.5. Где набор выпадает
  В zoneContent() (scrBalance) уже есть списки rewardAlways / rewardNightOnly /
  rewardAfterBoss / shopCards. Варианты для лесного набора:
   - отдельный список rewardForestSet, который подмешивается в пул после
     вступления Фиры в отряд (global.foxJoined) — логично по сюжету;
   - или часть карт — в магазин через shopCards.
  Подмешивание делается в forestRewardPool() (scripts/sprSpawnerUtils) одной
  строкой, как сейчас для карт марионеток.

2.6. Редкость: обычные и уникальные карты набора (решение 0.9)
  Второй аргумент registerCard — может ли карта быть разной редкости.
   - Обычная карта набора: true. Фабрика принимает rarity, числа берёт из
     cardBalance() по редкости. В наградах она может выпасть любой редкости
     из rewardRarities.
   - Уникальная карта набора: false. cardBuild сам подставит обычную редкость,
     что бы ни передали; setDeckSlot и unlockCard тоже приводят её к обычной.
     Числа у такой карты фиксированные, массив по редкости ей не нужен.
  Рамка карты выбирается по редкости, поэтому уникальная карта получит обычную
  рамку. Если уникальные должны выглядеть особо — добавь признак card.isUnique
  и свою рамку в cardBorderForRarity (scripts/scrCards).
  Сейчас в демо включён флаг REWARD_DEFAULT_RARITY_ONLY: в наградах всё равно
  выпадает только обычная редкость. Скейлинг по редкости станет заметен, когда
  флаг выключишь.

  Все четыре лесные карты сейчас обычные (true). Что у каждой растёт с редкостью:
    Сумка с припасами — число ингредиентов;
    Сбор припасов     — число ингредиентов или шанс не потерять карту;
    Зелье провокации  — длительность;
    Пустая колба      — сила каждой формы (урон, щит, лечение, число ходов).
  Это предложения, а не требования: главное, чтобы у каждой карты было хотя бы
  одно число, зависящее от редкости, и оно лежало в cardBalance().

Проверка: игра работает как раньше, у всех карт cardSet = Base.

================================================================================
  ЧАСТЬ 4. ОБЫЧНЫЕ КАРТЫ ТРАТЯТ ИНГРЕДИЕНТ
================================================================================

Правило: при розыгрыше карта смотрит на верхний ингредиент. Если он ей
подходит — забирает и усиливается (решение 0.2); не подходит — не трогает.

  Цветок   — сильнее лечение
  Гриб     — сильнее урон
  Листочек — негативные эффекты накладываются надёжнее

4.1. Подходит ли ингредиент карте
    function ingredientFitsCard(ingredient, card) {
        // пройти по card.effects:
        //   Flower   — есть эффект EffectTypes.Heal
        //   Mushroom — есть эффект EffectTypes.Damage
        //   Leaf     — есть эффект с шансом (variable_struct_exists(effect, "chance"))
        //              или дебафф/уязвимость
    }

4.2. Где забирать — шаг 4 в cardPlaySequence (scripts/scrCards)
  В начале шага 4, до цикла по эффектам:
    var usedIngredient = undefined
    var topIngredient = ingredientPeek(ctx.caster)
    if (topIngredient != undefined && ingredientFitsCard(topIngredient, ctx.card)) {
        usedIngredient = ingredientTake(ctx.caster)
    }
    ctx.caster.activeIngredient = usedIngredient     // «действует на эту карту»
  В конце шага 4, после цикла:
    ctx.caster.activeIngredient = undefined

  Почему поле на кастере, а не аргумент: функции эффектов
  (executeDamageEffect, executeHealing, effectApplyStatus) уже получают caster,
  но не получают ctx. Менять их подписи во всех вызовах дольше и рискованнее.
  В Starrior/Create добавь: activeIngredient = undefined.

  Помни про ловушку: шаг — это функция внутри with (Battle). Всё, что берёшь из
  ctx, читай через ctx.* — не через «голые» имена.

4.3. Три усиления — по одной строке
  Числа — в scrBalance:
    #macro INGREDIENT_HEAL_MULT 1.5
    #macro INGREDIENT_DAMAGE_MULT 1.5
    #macro INGREDIENT_STATUS_CHANCE_BONUS 0.4

  Урон — executeDamageEffect, после damage = cardMultiplier * casterStat:
    if (caster.activeIngredient == Ingredient.Mushroom) { damage *= INGREDIENT_DAMAGE_MULT }
  Лечение — executeHealing: значение эффекта умножить, если activeIngredient == Flower.
  Статусы — effectChanceForCaster: если activeIngredient == Leaf — base += бонус.
    (Там уже есть похожая прибавка за слабость цели — образец.)
    Для статусов без шанса (дебаффы) лист может прибавлять +1 ход длительности:
    в effectApplyStatus после наложения applied.duration += 1.

4.4. Карта, которая сама даёт ингредиент
  Порядок: сначала потратить (4.2), потом получить. Иначе карта съест то, что
  только что дала. Выдачу делай отдельным эффектом (часть 6), он сработает в
  цикле шага 4 — уже после того, как верхний ингредиент забран.

Проверка: выдай герою гриб, сыграй атаку — урон в полтора раза выше, гриб
пропал. Выдай цветок, сыграй атаку — цветок остался, урон обычный.

Эти три вещи нужны колбе и провокации. Сделай и проверь их отдельно.

5.1. Чистый урон (игнорирует защиту)
  Сейчас весь урон проходит mitigateDamage. Нужен обход.
  Вариант: новое значение DamageTypes.Pure (в конец enum).
   - в executeDamageEffect: для Pure не брать силу/интеллект как множитель —
     effect.value сразу готовое число; и не вызывать mitigateDamage;
   - в хуке onEndOfTurn у "Damage" (урон по времени): для Pure —
     character.applyDamage(rawValue) напрямую.
  Проверь getEffectDamageType и места, где damageType сравнивается с Magical:
  «не магический» сейчас означает «физический» — чистый урон не должен
  случайно попасть в физическую ветку.

5.2. Избыточное здоровье (щит)
  objects/Starrior/Create_0.gml:
    bonusHp = 0
  applyDamage(value): сначала списывать из bonusHp, остаток — из hp.
    var absorbed = min(bonusHp, value)
    bonusHp -= absorbed
    value -= absorbed
    // дальше как было: hp -= value
  Новая функция applyBonusHp(value): bonusHp += value (с потолком, например
  не больше половины maxHp — макрос в scrBalance) + всплывающее число.
  Отрисовка: полоска здоровья рисуется в Starrior/Draw_0 (drawHealthBarMana).
  Щит — отдельный сегмент другого цвета поверх или справа от полоски.
  Панели героев слева (drawPartyPanels) — там тоже стоит показать.
  Щит держится до конца боя и сам не сгорает (решение 0.8). В начале нового
  боя bonusHp = 0 — боец создаётся заново, отдельно сбрасывать не нужно.

5.3. Яд (чистый урон каждый ход)
  Это обычный урон по времени, только чистый. У тебя уже есть образец —
  Burn и Bleeding (DamageOverTimeEffect в scrEffectSystem):
    StatusNames: добавить Poison (в конец)
    function PoisonEffect(value, duration, chance) {
        return DamageOverTimeEffect(DamageTypes.Pure, value, duration, StatusNames.Poison, chance)
    }
  Иконка: statusNameIcon и weaknessIcon — добавить case (пока спрайта нет — noone).
  Название: weaknessLabel + ключ weakness.Poison в локализации.
  Тикает в конце хода отравленного — через существующий executeEndOfTurn.

5.4. «Негативный ли эффект» — понадобится колбе
    function effectIsNegative(effect) {
        // Debuff, Stun, Weakening, CreateTemporaryWeakness,
        // урон по времени (type Damage и есть duration): Burn, Bleeding, Poison,
        // а также Freeze, Shock по statusName
    }
  И две операции над целью:
    function extendNegativeEffects(target, turns)   // всем негативным duration += turns
    function removeOneNegativeEffect(target)        // убрать один (первый или случайный)
  executeRemoveStatus в scrCards — образец удаления по имени статуса.

Проверка: временной картой нанеси чистый урон врагу с защитой — проходит
полностью; дай герою щит — урон сначала съедает его; отрави врага — каждый
его ход он теряет здоровье, защита не помогает.

6.2. Сумка с припасами — «достаёт 1 случайный ингредиент, тратит всю энергию»
  Фабрика (новый скрипт scrCardFactoryForest):
    цель TargetTypes.Self, действие StarriorStates.Cast,
    эффекты [ GainIngredientEffect(1) ], категория CardCategory.Special.
  «Тратит всю энергию». В шаге 4 стоит ctx.caster.energy -= ctx.card.energy.

    else { ctx.caster.energy -= ctx.card.energy }
  (поле по умолчанию false в конструкторе Card).
  Сейчас у героев энергии обычно 1, так что разница видна только с картой
  «дополнительная энергия» — но правило лучше заложить сразу.
  Цена карты — вся энергия (решение 0.10). Я понимаю это так, что маны она не
  стоит. Но цена в мане считается автоматически: computeCardCost смотрит на
  первый эффект, новый тип попадёт в ветку other и получит обычную цену.
  Поэтому в фабрике задай явно: card.costValueCached = 0. Если мана тоже
  должна тратиться — просто не обнуляй.
  Что растёт с редкостью: у Сумки это может быть число ингредиентов
  (например [1, 1, 2, 2]) — значение бери из cardBalance().

6.3. Сбор припасов — «потеряй случайную карту в руке, получи 1 ингредиент»
  Новый эффект DiscardRandomCard (тот же путь: EffectTypes, case, реестр, конструктор):
    onPlay: function(effect, caster, targets) {
        var hand = caster.getCardsInHand()
        if (array_length(hand) == 0) { return }
        var lost = hand[irandom(array_length(hand) - 1)]
        removeCardFromHand(caster, lost)
        // TODO: показать, какая карта потеряна (анимация или всплывающий текст)
    }
  Эффекты карты: [ DiscardRandomCardEffect(), GainIngredientEffect(1) ].
  Сама карта «Сбор припасов» к этому моменту уже убрана из руки (шаг 1),
  потеряется одна из ОСТАЛЬНЫХ. Если других карт нет — карту всё равно можно
  сыграть, ингредиент выдаётся (решение 0.11). Проверка на пустую руку в хуке
  уже стоит, в checkIfCanPlayCard ничего добавлять не нужно.
  Что растёт с редкостью: например число ингредиентов или шанс не потерять
  карту. Выбери одно и положи числа в cardBalance().

Проверка: Сумка даёт ингредиент и заканчивает ход; Сбор убирает случайную
карту из руки и даёт ингредиент.


================================================================================
  ЧАСТЬ 7. ЗЕЛЬЕ ПРОВОКАЦИИ
================================================================================

«Заставляет врагов атаковать персонажа. За каждый ход под провокацией —
1 случайный ингредиент.»

7.1. Статус
  EffectTypes: Provoke (в конец), StatusNames: Provoke (в конец), case в
  effectKindFromType.
    function ProvokeEffect(duration) {
        return { type: EffectTypes.Provoke, statusName: StatusNames.Provoke,
                 duration: duration, timing: Timing.EndOfTurn, sprite: buffEffect }
    }
  Почему Timing.EndOfTurn: такие статусы в конце хода владельца вызывают хук
  onEndOfTurn и уменьшают длительность (executeEndOfTurn в scrCards). Как раз
  то, что нужно для «каждый ход под провокацией»:
    variable_struct_set(effectsRepository, "Provoke", {
        onEndOfTurn: function(effect, character) { ingredientAddRandom(character) },
        icon: ProvokeIcon     // пока нет спрайта — noone
    })

  Проверь в executeEndOfTurn: длительность уменьшается только если у обработчика
  есть onEndOfTurn — у нас есть. Статус, наложенный в этом же ходу, тикнет уже
  в конце этого хода: длительность 2 = «конец этого хода + конец следующего».
  Посчитай на бумаге, сколько кругов врагов он реально прикрывает, и подбери число.

7.2. Враги бьют провокатора
  objects/Battle/Alarm_0.gml — там четыре вызова enemyResolveTarget (лечение,
  бафф, атака, случайная карта). Последний аргумент (preferFoe) везде noone.
  Найди провокатора:
    function provokingFoe(foes) {
        // первый из foes, у кого checkIfHasEffectType(foe, EffectTypes.Provoke)
        // нет такого — noone
    }
  и передавай его как preferFoe в вызове для атаки и в вызове для случайной
  карты (она тоже может оказаться атакой). В вызовах лечения и баффа не нужно.
  enemyResolveTarget уже умеет: для SingleEnemyTarget вернёт preferFoe, для
  AllEnemies — всех (провокация не влияет, решение 0.6).

  Куклы врага — runPuppetTurn (scripts/sprPuppetManagement): там цель среди
  foes выбирается отдельно; добавь ту же проверку.

  Если провокатор пал — isKO(): aliveHeroes его уже не содержит, функция вернёт
  noone, враги бьют как обычно.

7.3. Карта
  Цель Self, действие Cast, эффекты [ ProvokeEffect(<длительность>) ],
  категория Buff («усиливающая»). Длительность по редкости — в cardBalance.
  В описании используй метку {turns} — длительность подставится сама.

7.4. Связки
  - Провокация + Дефлект (если сделал): все бьют в героя, а он отражает.
  - Провокация + избыточное здоровье: танк.
  - Враги с лечением/баффом провокацию игнорируют — они не атакуют.

Проверка: сыграл зелье — над героем значок; враги одиночными атаками бьют
только его; в конце каждого его хода +1 ингредиент; статус сам снимается.


================================================================================
  ЧАСТЬ 8. ПУСТАЯ КОЛБА
================================================================================

Семь форм в зависимости от ингредиентов:
  нет           — очень маленький физический урон врагу
  цветок(и)     — избыточное здоровье герою (сила от количества)
  гриб(ы)       — чистый урон врагу (сила от количества)
  листочек(и)   — продлить негативные эффекты на враге (ходы от количества)
  цветок+гриб   — физ. атака с похищением здоровья (излишек — в щит)
  цветок+лист   — лечение + снять негативный эффект
  гриб+лист     — физ. атака с шансом отравления

8.1. В чём сложность
  У формы меняется не только эффект, но и ЦЕЛЬ: враг, союзник. А цель карты —
  поле card.target, по которому бой решает, какой выбор показать игроку
  (шаг CharacterPlay). Эффекты — поле card.effects, по которому идёт розыгрыш.
  Описание — по id карты.

8.2. Решение: перестраивать карту на месте
  Не трогаем ни выбор цели, ни розыгрыш. Вместо этого сама карта «переодевается»
  каждый раз, когда у владельца меняется запас ингредиентов:
    card.target, card.effects, card.formKey  — пересчитываются.
  Тогда весь существующий код работает как с обычной картой.

  Enum форм (scrBattleEnums):
    enum FlaskForm { Empty, Flower, Mushroom, Leaf, FlowerMushroom, FlowerLeaf, MushroomLeaf }

  Определить форму по запасу:
    function flaskFormFor(ingredients) {
        // TODO: посчитать, сколько каждого вида (максимум два ингредиента всего)
        // пусто -> Empty; один вид -> Flower/Mushroom/Leaf; два разных -> комбинация
    }

  Построить содержимое формы:
    function flaskBuild(form, amount, rarity) {
        // amount — сколько ингредиентов (1 или 2), для силы
        switch (form) {
            case FlaskForm.Empty:
                return { target: TargetTypes.SingleEnemyTarget,
                         effects: [ DamageEffect(DamageTypes.Physical, <маленький множитель>) ] }
            case FlaskForm.Flower:
                return { target: TargetTypes.SingleAllyTarget,
                         effects: [ BonusHpEffect(<значение> * amount) ] }
            // TODO: остальные пять
        }
    }
  Новые эффекты, которые понадобятся формам (тот же путь, что в части 6):
    BonusHpEffect(value)            — onInstant: applyBonusHp
    ExtendNegativeEffect(turns)     — onInstant: extendNegativeEffects
    RemoveNegativeEffect()          — onInstant: removeOneNegativeEffect
    LifestealDamage                 — см. 8.4

  Перестроить карту:
    function flaskRefresh(card, owner) {
        var form = flaskFormFor(owner.ingredients)
        var built = flaskBuild(form, array_length(owner.ingredients), card.rarity)
        card.target = built.target
        card.effects = built.effects
        card.flaskForm = form
    }

8.3. Когда перестраивать
  Функция из части 3:
    function refreshDynamicCards(character) {
        // пройти по руке И по колоде бойца (getOriginalDeck / shuffeledDeck),
        // у карт с card.isFlask вызвать flaskRefresh(card, character)
    }
  Вызывается из ingredientAdd / ingredientTake / ingredientTakeAll и один раз
  в начале боя (после раздачи руки). Карты в руке и в колоде — одни и те же
  структуры (раздача копирует ссылки), поэтому достаточно обновить каждую.

  Почему не «в момент розыгрыша»: игрок должен ВИДЕТЬ, во что превратится колба,
  до того как нажмёт. Форма должна быть актуальна всё время, пока карта в руке.

8.4. Колба тратит все ингредиенты
  Общее правило из части 4 (обычная карта тратит один верхний) колбе не
  подходит. В шаге 4 cardPlaySequence:
    if (ctx.card.isFlask) {
        ingredientTakeAll(ctx.caster)
        // activeIngredient не ставим: сила уже заложена в эффекты формы
    } else {
        // обычное правило из 4.2
    }
  ВНИМАНИЕ на порядок: ingredientTakeAll вызовет refreshDynamicCards, и колба
  перестроится в «пустую» форму — её effects заменятся ПРЯМО ВО ВРЕМЯ розыгрыша.
  В шаге 4 уже есть строка var effects = ctx.card.effects, и цикл идёт по этой
  локальной переменной. Забирай ингредиенты строго ПОСЛЕ неё: тогда цикл
  отработает по старому списку, даже если карта уже перестроилась. Если
  поставить ingredientTakeAll раньше — сыграется «пустая» форма.
  К этому моменту колба уже убрана из руки (шаг 1), но в колоде она есть,
  поэтому перестройка её и затрагивает.

  Похищение здоровья (форма цветок+гриб). Сейчас вампиризм срабатывает с шансом
  и лечит через applyHeal (без излишка). Нужен гарантированный вариант с
  переливом в щит: после нанесения урона
    var stolen = round(damage * <доля>)
    var missing = caster.maxHp - caster.hp
    caster.applyHeal(min(stolen, missing))
    if (stolen > missing) { caster.applyBonusHp(stolen - missing) }
  Проще всего — признак на эффекте (effect.lifesteal = <доля>) и ветка в
  executeDamageEffect рядом с существующим вампиризмом.

8.5. Текст и вид карты
  Описание берётся по id карты (cardDisplayDesc -> card.desc.<id>). Для колбы —
  по форме: в cardDisplayDesc, если card.isFlask, бери ключ
    "card.desc.emptyFlask." + <имя формы>
  и заведи семь текстов на каждом языке.
  Иллюстрацию тоже можно менять по форме (card.cardIllustrationSpr в flaskRefresh).

  КЭШ. cardFaceLayout (scripts/scrDrawing) запоминает подобранный текст по
  ключу «имя | редкость | язык | размер | длительность». У колбы имя и редкость
  не меняются, а текст меняется — без правки на карте застрянет старое описание.
  Добавь в ключ форму: + "|" + string(card[$ "flaskForm"]).

8.6. Цена
  Тип цены (мана/здоровье) определяется типом действия при создании карты и
  кэшируется. Колба всегда Cast (мана) — менять не надо. Величина цены считается
  по первому эффекту в момент создания; у колбы эффекты меняются, а цена
  останется от «пустой» формы. Это нормально, просто задай ей осмысленную цену
  явно (card.costValueCached = ...).

8.7. Враги и колба
  ИИ врага выбирает карту по категории и эффектам. Динамическая карта у врага —
  источник странностей. Не давай колбу врагам, исключи в enemyPlayableCards.
  Кража: герой может украсть только карты из руки врага — если колбы у врагов
  нет, вопрос снимается.

Проверка: без ингредиентов колба — слабый удар по врагу; с цветком — выбор
союзника и щит; с грибом — чистый урон; набери два разных — форма сменилась,
текст на карте сменился; после розыгрыша запас пуст.


================================================================================
  ЧАСТЬ 9. ЧТО ПОКАЗАТЬ ИГРОКУ
================================================================================

Без этого механику никто не поймёт.

9.1. Запас ингредиентов
  Рядом с героем в бою — два слота со значками (пустой / цветок / гриб / лист).
  Рисовать в objects/Starrior/Draw_0.gml рядом с иконками статусов или в
  панели героя слева (drawPartyPanels) — лучше в обоих местах.
  Верхний (тот, что уйдёт первым) выдели: крупнее или с рамкой.

9.2. Получение и трата
  Всплывающий значок над героем при получении (в проекте есть drawDamageNumber —
  образец всплывающего текста). При трате — короткая вспышка значка.

9.3. Какая карта возьмёт ингредиент
  В руке подсвети карты, которым подходит верхний ингредиент
  (ingredientFitsCard(ingredientPeek(selectedCharacter), card)). Иначе игрок не
  поймёт, почему одна атака сильнее другой.

9.4. Колба
  Меняющиеся текст и иллюстрация (8.5). Можно добавить на карту мини-значки
  текущих ингредиентов.

9.5. Окно «Инфо»
  Строка «Ингредиенты: …», щит («Избыточное здоровье: N»), статусы Провокация
  и Отравление с описаниями (ключи status.name.* / status.desc.*).

9.6. Обучение
  Механика большая. Реплика Фиры при вступлении в отряд или подсказка при
  первом ингредиенте сэкономит игроку много непонимания.


================================================================================
  ЧАСТЬ 10. ПОРЯДОК, ЧЕК-ЛИСТ, ЧАСТЫЕ ОШИБКИ
================================================================================

Порядок внедрения (после каждого шага игра должна работать):
  1. Часть 2 — CardSet, поле cardSet.
  2. Часть 3 — запас ингредиентов + отладочная клавиша выдачи.
  3. Часть 9.1 — значки запаса (сразу, иначе дальше работаешь вслепую).
  4. Часть 4 — обычные карты тратят ингредиент.
  5. Часть 6 — Сумка и Сбор припасов (первые настоящие лесные карты).
  6. Часть 5 — чистый урон, щит, яд.
  7. Часть 7 — провокация.
  8. Часть 8 — колба: сначала формы без ингредиента и с одним, потом комбинации.
  9. Часть 9 — остальные подсказки, тексты, баланс.

Чек-лист:
  [ ] Старые карты и бои работают как раньше.
  [ ] Запас не больше двух; третий вытесняет самый старый.
  [ ] Гриб усиливает урон, цветок — лечение, лист — статусы; неподходящий
      ингредиент остаётся в запасе.
  [ ] В начале нового боя запас пуст.
  [ ] Сумка даёт ингредиент и забирает всю энергию.
  [ ] Сбор убирает случайную карту из руки (не себя) и даёт ингредиент.
  [ ] Провокация: одиночные атаки врагов идут в героя; ингредиент каждый ход;
      статус снимается сам; павший провокатор никого не притягивает.
  [ ] Чистый урон игнорирует защиту; щит принимает урон первым; яд тикает.
  [ ] Колба: все семь форм, правильная цель у каждой, текст меняется,
      запас обнуляется после розыгрыша.
  [ ] Колба с двумя одинаковыми ингредиентами сильнее, чем с одним.
  [ ] Значки запаса видны; понятно, какая карта возьмёт ингредиент.
  [ ] Тексты на русском и английском; новые enum-значения добавлены в конец.
  [ ] Лесные карты выпадают/продаются так, как задумано.

Частые ошибки:
  * Карта съедает ингредиент, который сама только что дала — перепутан порядок
    «потратить, потом получить».
  * Колба перестроилась во время собственного розыгрыша и сыграла «пустую»
    форму — ingredientTakeAll вызван раньше, чем эффекты сохранены в локальную
    переменную (8.4).
  * На колбе старый текст — форма не добавлена в ключ кэша cardFaceLayout.
  * Чистый урон попал в физическую ветку (сравнение «не магический = физический»)
    и режется защитой.
  * Лечение обрезается по maxHp — избыточное здоровье не появляется: нужен
    отдельный bonusHp, а не hp выше максимума.
  * Щит не учитывается в applyDamage — урон идёт мимо него.
  * Провокация притягивает и удары по группе, и лечение врагов — проверяй тип
    цели карты врага.
  * Новый вид эффекта добавлен в EffectTypes, но нет case в effectKindFromType —
    хук молча не вызывается.
  * Значение enum вставлено в середину — сдвигаются числа остальных.
  * activeIngredient не сброшен после шага 4 — следующая карта получает чужой бонус.
  * Внутри with (Battle) обращение к параметру функции — он ищется как поле
    Battle. Данные шага бери через ctx.
  * Числа (множители, длительности, потолок щита) в коде фабрик — собери
    в scrBalance / cardBalance().
  * Лесные карты попали врагам — ИИ не умеет ни копить ингредиенты, ни играть
    колбу. Исключи их в enemyPlayableCards.


Совет: не начинай с колбы. Сделай запас ингредиентов со значками и одно
усиление (гриб -> урон) — это день работы, и механика уже «играется».
Сумка и Сбор добавляются за час. Колба — последняя: к этому моменту все её
составные части (щит, чистый урон, яд, работа с негативными эффектами) уже
будут готовы и проверены по отдельности.
