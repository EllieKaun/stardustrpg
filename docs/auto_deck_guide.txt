  АВТОСБОРКА КОЛОДЫ: «НЕ ОПТИМАЛЬНО, НО ИГРАБЕЛЬНО»
  Гайд по реализации. Проект: stardustrpg (GameMaker, GML)
================================================================================

Формат как у прошлых гайдов: решения, карта кода, части с готовым кодом,
чек-лист и частые ошибки. Номера строк — по ветке feature/ai-enemy-decision.

Что получится:
  - в декбилдере над колодой кнопка «АВТО [G]» (и клавиша G);
  - она пересобирает колоду ОТКРЫТОГО героя из свободных карт коллекции;
  - колода собирается по шаблону: урон своей роли, восстановление своего
    ресурса, бафф, дальше ещё урон и «что угодно»;
  - внутри шаблона карта выбирается случайно из «полосы» лучших по очкам:
    повторное нажатие даёт другой, тоже рабочий вариант;
  - если в колоде уже есть карты, сначала спрашивается подтверждение.

================================================================================
  ЧАСТЬ 0. ПРИНЯТЫЕ РЕШЕНИЯ
================================================================================

0.1. Собирается колода только текущего героя (editingCharacter).
  Колоды остальных не трогаем. Их карты остаются у них: автосборка берёт
  только свободные копии.

0.2. Карты — из любого набора.
  Лесные карты наравне с остальными, без штрафа и без бонуса.

0.3. Если в колоде героя уже есть карты — подтверждение.
  Пустую колоду собираем сразу, без вопроса.

0.4. Фиксированные слоты спутника не трогаем.
  У спутников (Сафар, Фира) первые deckFixedSlots(character) слотов зашиты.
  Автосборка заполняет только слоты от deckFixedSlots до deck.unlocked.

0.5. Колода собирается с нуля, а не «дополняется».
  Сначала все нефиксированные слоты героя очищаются, его копии возвращаются в
  пул, потом слоты заполняются заново. Так результат не зависит от того, что
  лежало раньше. Кнопка «дополнить только пустые слоты» — в 9.5.

0.6. Играбельно = три правила.
  - есть урон своего типа (Лане — магия, Вив — физика), если такие карты есть;
  - есть восстановление своего ресурса: Лане — мана (её касты стоят ману),
    Вив — лечение (её атаки стоят здоровье);
  - не набирать одинаковых карт, пока есть разные.
  Остальное решают очки. Это не оптимизатор, и не должен им быть.

0.7. Нет подходящей карты — берём лучшую из оставшихся. Нет вообще никаких
  свободных карт — слот остаётся пустым. Автосборка никогда не падает и не
  кладёт то, чего нет в коллекции.


================================================================================
  ЧАСТЬ 1. КАРТА КОДА: НА ЧТО ОПИРАЕМСЯ
================================================================================

scripts/scrCollectionDecks/scrCollectionDecks.gml — всё для работы с колодой:
  deckOf(character)           — { unlocked, cards: [{ slot, id, rarity }] }
  deckFixedSlots(character)   — сколько первых слотов зашито (у героев 0)
  clearDeckSlot(character, slot)
  setDeckSlot(character, slot, id, rarity) — сам проверяет владение, свободные
                                копии и границы слотов, возвращает true/false
  freeCopies(id, rarity)      — копии, не занятые НИ ОДНОЙ колодой
  getCollectionRefs()         — [{ id, rarity, count }]
  cardFromRef(ref)            — построить карту
  deckPutCard(character, slot, ref) — setDeckSlot + аналитика

scripts/scrCards/scrCards.gml, Card:
  actionType   — StarriorStates.Attack (стоит HP) или Cast (стоит ману)
  effects[]    — { type: EffectTypes.*, damageType, ... }
  rarity       — CardsRarity.Default..Epic (0..3)
  costValue()  — цена

scripts/scrBattleEnums: EffectTypes (Damage, Heal, ManaGain, Buff, Debuff,
  Weakening, CreateTemporaryWeakness, Provoke, ...), DamageTypes (Physical,
  Magical, True), CardCategory (Attack, Magic, Heal, Buff, Special),
  cardCategoryOf(card) — категория из реестра.

objects/oDeckBuilder:
  Create_0: editingCharacter, deckPanel, applyChanges() — пересобрать обе
            панели и сохранить
  Step_0:   стр. 18–23 — мышь и клавиатура панелей
  Draw_64:  стр. 14–15 — отрисовка панелей

Занятые клавиши декбилдера: WASD и стрелки, Q/E (вкладки), Enter/Space,
Tab/Esc (закрыть). G свободна.

Почему роль героя берём из таблицы, а не из статов. Статы (сила, интеллект,
мана) задаются в createLana/createViv (scrStarriorsInitializer) при создании
бойца в БОЮ. В декбилдере бойцов нет, а создавать их ради статов — лишнее.
Таблица из четырёх строк проще и честнее (часть 2).


================================================================================
  ЧАСТЬ 2. РОЛЬ ГЕРОЯ
================================================================================

Новый скрипт scrAutoDeck — создай его В IDE (правой кнопкой по Scripts ->
Create Script) и вставляй код туда. Скрипт, созданный снаружи, придётся
руками прописывать в stellarpunk_rpg.yyp при закрытой IDE.

    function autoDeckRole(character) {
        switch (character) {
            case Characters.Viv: return { damageType: DamageTypes.Physical, recovery: EffectTypes.Heal }
            case Characters.Safar: return { damageType: undefined, recovery: EffectTypes.Heal }
            case Characters.Fox: return { damageType: DamageTypes.Magical, recovery: EffectTypes.ManaGain }
            default: return { damageType: DamageTypes.Magical, recovery: EffectTypes.ManaGain }
        }
    }

  Откуда роли:
    Лана  — сила 4, интеллект 10, HP 30  -> магия, восстанавливает ману;
    Вив   — сила 10, интеллект 4, HP 70  -> физика, лечится;
    Сафар — сила 8, интеллект 8          -> любой урон (undefined), лечится;
    Фира  — сила 6, интеллект 10         -> магия, мана.
  Магический урон в проекте — всегда Cast (стоит ману), физический — Attack
  (стоит HP). Поэтому тип урона заодно задаёт, каким ресурсом герой платит.
  Новый герой — новая строка в switch.


================================================================================
  ЧАСТЬ 3. ВИД КАРТЫ
================================================================================

Шаблону нужен ответ на вопрос «это какая карта»: урон, восстановление, бафф
или прочее.

    function autoDeckHasEffect(card, effectType) {
        for (var effectIndex = 0; effectIndex < array_length(card.effects); effectIndex++) {
            if (card.effects[effectIndex].type == effectType) { return true }
        }
        return false
    }

    function autoDeckDamageType(card) {
        for (var effectIndex = 0; effectIndex < array_length(card.effects); effectIndex++) {
            var effect = card.effects[effectIndex]
            if (effect.type == EffectTypes.Damage) { return effect[$ "damageType"] }
        }
        return undefined
    }

    function autoDeckKindOf(card) {
        if (autoDeckHasEffect(card, EffectTypes.Heal) || autoDeckHasEffect(card, EffectTypes.ManaGain)) { return "recovery" }
        if (autoDeckDamageType(card) != undefined) { return "damage" }
        if (cardCategoryOf(card) == CardCategory.Buff) { return "buff" }
        return "other"
    }

  Сначала проверяется восстановление: если появится карта «урон + лечение»,
  она займёт слот восстановления, а это важнее. Вампиризм (VampirismEffect) —
  эффект типа Damage без отдельного Heal, поэтому он «урон».
  Лечение по времени (HealOverTimeEffect) тоже имеет type Heal — считается
  восстановлением, как и должно.
  Категория Buff в реестре — это и баффы своих, и дебаффы/слабости врага, и
  Зелье провокации. Для «играбельной» колоды это всё одинаково полезно.
  Пустая колба вне боя — «пустая» форма с физическим уроном, поэтому для
  автосборки она «урон». Это нормально: её форма в бою всё равно меняется.


================================================================================
  ЧАСТЬ 4. ШАБЛОН КОЛОДЫ
================================================================================

В scrBalance, рядом с остальными числами баланса:

    #macro AUTO_DECK_TEMPLATE ["damage", "recovery", "damage", "buff", "damage", "any", "recovery", "damage", "buff", "any", "damage", "any"]

  Слот колоды номер N (считая от первого нефиксированного) берёт вид
  AUTO_DECK_TEMPLATE[N]. Значит, шаблон сам подстраивается под число открытых
  слотов:
    4 слота  (старт)        — урон, восстановление, урон, бафф
    5 слотов                — + урон
    6 слотов (максимум леса) — + любая
    12 слотов (DECK_CAPACITY) — шаблон рассчитан и на это.
  "any" — вид не важен, решают остальные очки.
  Порядок в шаблоне = порядок выбора. Сначала самые важные слоты: если карт
  мало, лучшие достанутся урону и восстановлению.

  Почему макрос-массив, а не функция: так же сделаны ZONE_DECK_SLOT_LIMITS и
  EMPTY_WEB_SLOT_INDICES. Меняется в одном месте, без кода.


================================================================================
  ЧАСТЬ 5. ОЧКИ КАРТЫ
================================================================================

Числа — в scrBalance:

    #macro AUTO_DECK_KIND_BONUS 10
    #macro AUTO_DECK_ROLE_BONUS 6
    #macro AUTO_DECK_RARITY_BONUS 2
    #macro AUTO_DECK_COST_WEIGHT 0.2
    #macro AUTO_DECK_DUPLICATE_PENALTY 5
    #macro AUTO_DECK_SPREAD 4

Функция (scrAutoDeck):

    function autoDeckFitsRole(card, role) {
        var damageType = autoDeckDamageType(card)
        if (damageType != undefined) { return role.damageType == undefined || damageType == role.damageType }
        if (autoDeckHasEffect(card, EffectTypes.Heal) || autoDeckHasEffect(card, EffectTypes.ManaGain)) {
            return autoDeckHasEffect(card, role.recovery)
        }
        return true
    }

    function autoDeckScore(card, cardId, role, wantedKind, placedIds) {
        var score = 0
        if (wantedKind == "any" || autoDeckKindOf(card) == wantedKind) { score += AUTO_DECK_KIND_BONUS }
        if (autoDeckFitsRole(card, role)) { score += AUTO_DECK_ROLE_BONUS }
        score += card.rarity * AUTO_DECK_RARITY_BONUS
        score -= card.costValue() * AUTO_DECK_COST_WEIGHT
        for (var placedIndex = 0; placedIndex < array_length(placedIds); placedIndex++) {
            if (placedIds[placedIndex] == cardId) { score -= AUTO_DECK_DUPLICATE_PENALTY }
        }
        return score
    }

  Как читать числа:
    - «нужный вид» (10) важнее «своей роли» (6): в слот восстановления Лана
      скорее возьмёт лечение, чем ещё одну магическую атаку, даже если маны
      в коллекции нет;
    - чужой урон получает 10, свой — 16. Свой урон почти всегда выигрывает, но
      если своего нет совсем, Лана возьмёт физическую атаку, а не пустой слот;
    - редкость: +2 за ступень;
    - цена: -0.2 за единицу. Дорогая карта не запрещена, просто проигрывает
      равной дешёвой;
    - дубликат: -5 за каждую такую же уже положенную карту. Две одинаковые
      возможны, только если альтернатива сильно хуже;
    - AUTO_DECK_SPREAD (4) — ширина «полосы», из которой выбирается карта
      (6.2). В очки случайность не добавляется: очки честно говорят, насколько
      карта подходит, а случайность живёт только в выборе.

  Почему полоса, а не «очки + случайная добавка». Добавка 0..3 меняла бы
  выбор только между картами с почти равными очками: карта лучше на 3+ очка
  (например, на две ступени редкости) выигрывала бы всегда, и колоды почти не
  менялись бы. Поднять добавку тоже нельзя: при 6+ Лана начала бы брать
  физические атаки. Полоса решает обе проблемы сразу:
    - всё, что отстаёт от лучшей карты не больше чем на 4 очка, — равноправные
      кандидаты, выбор между ними случайный;
    - карты чужой роли (-6), не того вида (-10) и повторы (-5) в полосу не
      попадают, пока есть что-то подходящее, — гарантии шаблона сохраняются.
  Чтобы разрывы оставались больше полосы, AUTO_DECK_SPREAD держи меньше
  AUTO_DECK_DUPLICATE_PENALTY и AUTO_DECK_ROLE_BONUS.

  ЧАСТЬ 6. СБОРКА

6.1. Кандидаты — один раз, а не на каждый слот

    function autoDeckCandidates() {
        var candidates = []
        var refs = getCollectionRefs()
        for (var refIndex = 0; refIndex < array_length(refs); refIndex++) {
            var cardRef = refs[refIndex]
            if (cardRef.count <= 0) { continue }
            var card = cardFromRef(cardRef)
            if (card == undefined) { continue }
            array_push(candidates, { ref: { id: cardRef.id, rarity: cardRef.rarity }, card: card })
        }
        return candidates
    }

  Карта строится через cardFromRef один раз на запись коллекции (id + редкость).
  Строить её внутри цикла по слотам — 6 слотов × 30 карт = 180 вызовов фабрик
  вместо 30.

6.2. Выбор из полосы

    function autoDeckPick(scored) {
        if (array_length(scored) == 0) { return undefined }
        var bestScore = -infinity
        for (var scoredIndex = 0; scoredIndex < array_length(scored); scoredIndex++) {
            bestScore = max(bestScore, scored[scoredIndex].score)
        }
        var band = []
        for (var scoredIndex = 0; scoredIndex < array_length(scored); scoredIndex++) {
            if (scored[scoredIndex].score >= bestScore - AUTO_DECK_SPREAD) { array_push(band, scored[scoredIndex]) }
        }
        return band[irandom(array_length(band) - 1)]
    }

  scored — массив { candidate, score }. Два прохода: сначала найти лучший
  счёт, потом собрать всех, кто к нему близок, и взять одного наугад.
  irandom(n) — целое от 0 до n включительно, поэтому n = длина - 1.
  randomize() уже вызывается в первой строке oGameController/Create_0.gml,
  поэтому irandom при каждом запуске игры даёт разные значения.

6.3. Главная функция

    function autoBuildDeck(character) {
        var deck = deckOf(character)
        var firstSlot = deckFixedSlots(character)
        for (var slot = firstSlot; slot < deck.unlocked; slot++) { clearDeckSlot(character, slot) }

        var role = autoDeckRole(character)
        var candidates = autoDeckCandidates()
        var template = AUTO_DECK_TEMPLATE
        var placedIds = []

        for (var slot = firstSlot; slot < deck.unlocked; slot++) {
            var wantedKind = template[min(slot - firstSlot, array_length(template) - 1)]
            var scored = []
            for (var candidateIndex = 0; candidateIndex < array_length(candidates); candidateIndex++) {
                var candidate = candidates[candidateIndex]
                if (freeCopies(candidate.ref.id, candidate.ref.rarity) <= 0) { continue }
                array_push(scored, {
                    candidate: candidate,
                    score: autoDeckScore(candidate.card, candidate.ref.id, role, wantedKind, placedIds)
                })
            }
            var picked = autoDeckPick(scored)
            if (picked == undefined) { break }
            var chosen = picked.candidate
            if (setDeckSlot(character, slot, chosen.ref.id, chosen.ref.rarity)) { array_push(placedIds, chosen.ref.id) }
        }
        return array_length(placedIds)
    }

  Почему freeCopies проверяется на КАЖДОМ слоте: после setDeckSlot копия
  занята, и freeCopies это уже учитывает. Отдельно считать «сколько осталось»
  не нужно — источник правды один.
  Очистка в начале возвращает в пул копии ТОЛЬКО этого героя. Карты в колодах
  Вив и спутника автосборка Ланы не увидит — так и задумано (решение 0.1).
  setDeckSlot, а не deckPutCard: deckPutCard шлёт событие аналитики на каждую
  карту. Если автосборку тоже нужно мерить — одно событие на всю сборку, 9.4.
  Функция возвращает число положенных карт — пригодится для сообщения
  «Не хватает карт» (9.3).

Проверка (временно, до кнопки): в oDeckBuilder Step_0 в самом конце

    if (keyboard_check_pressed(vk_f8)) {
        show_debug_message("auto: " + string(autoBuildDeck(editingCharacter)))
        applyChanges()
    }

  Новая игра, открой декбилдер на Лане, F8. В колоде должна быть магическая
  атака и карта маны (если её копия свободна). Нажми F8 ещё раз — состав может

Нужно, только если в колоде героя уже что-то лежит. deck.cards хранит только
нефиксированные карты (фиксированные спутника берутся из companionFixedRefs),
так что проверка простая:

    deckHasCards = function(character) {
        return array_length(deckOf(character).cards) > 0
    }

Есть два варианта окна. Выбери по тому, сделано ли уже единое окно из
unified_modal_guide.txt.

8.1. Если единое окно (modalConfirm) уже есть — Create_0:

    requestAutoDeck = function() {
        if (!deckHasCards(editingCharacter)) {
            runAutoDeck()
            return
        }
        var confirmBuild = method(self, function() { runAutoDeck() })
        modalOpen(modalConfirm(loc("deck.autoTitle"), loc("deck.autoWarn"), [
            { label: loc("deck.autoYes"), onSelect: confirmBuild },
            { label: loc("deck.autoNo") }
        ], { canCancel: true }))
    }

  И в Step_0 декбилдера должен стоять общий стоп из того гайда (8.6):
  if (modalIsOpen()) { exit } — ПЕРЕД кодом из 7.2. Иначе G, нажатая в окне,
  откроет второе окно.

8.2. Если единого окна ещё нет — «нажми ещё раз»
  Без отдельного окна: первое нажатие взводит подтверждение на 2 секунды,
  второе — собирает. Create_0:

    autoDeckArmedUntil = 0

    requestAutoDeck = function() {
        if (!deckHasCards(editingCharacter) || current_time < autoDeckArmedUntil) {
            autoDeckArmedUntil = 0
            runAutoDeck()
            return
        }
        autoDeckArmedUntil = current_time + 2000
    }

  Draw_64, вместо подписи из 7.3:

    var armed = (current_time < autoDeckArmedUntil)
    var autoLabel = armed ? loc("deck.autoAgain") : loc("deck.auto")
    draw_set_color(armed ? c_red : (autoDeckHover ? c_yellow : c_white))
    drawUiText(autoRect.x + autoRect.w / 2, autoRect.y + autoRect.h / 2, autoLabel, autoRect.h * 0.55, autoRect.w * 0.9)

  Ключ: deck.autoAgain = "ЕЩЁ РАЗ?" / "AGAIN?".
  Когда сделаешь единое окно — замени requestAutoDeck на 8.1, остальное не
  меняется.

Проверка: пустая колода — G собирает сразу. Колода с картами — сначала
вопрос; «Отмена» или ПКМ — ничего не изменилось; «Собрать» — колода новая.


================================================================================
  ЧАСТЬ 9. НАСТРОЙКА И РАСШИРЕНИЕ
================================================================================

9.1. Колода «не такая»
  Сначала AUTO_DECK_SPREAD 0 (полоса из одной лучшей карты, колода всегда
  одинаковая) и show_debug_message в autoBuildDeck после autoDeckPick: для
  каждого слота вид, выбранная карта и её очки. Почти всегда причина видна
  сразу: не тот вид у карты (часть 3) или не те веса (часть 5).

    show_debug_message(string(slot) + " " + wantedKind + " -> " + chosen.ref.id + " " + string(picked.score))

  Если колоды кажутся слишком одинаковыми — расширь полосу (5), слишком
  случайными — сузь (2–3). Шире AUTO_DECK_DUPLICATE_PENALTY не делай: в
  полосу начнут попадать повторы.

9.2. Запретить карту автосборке
  Если какая-то карта «технически подходит», но в автоколоде только мешает:

    #macro AUTO_DECK_SKIP_IDS ["shuffleDeck"]

  и в autoDeckCandidates: if (array_contains(AUTO_DECK_SKIP_IDS, cardRef.id)) { continue }
  Строки, а не global.CardId.*: макрос подставляется до того, как
  global.CardId создан. id карт и так равны своим именам (cardIdsInit).

9.3. Сообщить, что карт мало
  autoBuildDeck возвращает число положенных карт. Если меньше, чем слотов
  (deck.unlocked - deckFixedSlots), можно показать подсказку «Не хватает
  свободных карт — часть занята другими героями» (тем же modalConfirm с одной
  кнопкой или строкой под кнопкой).

9.4. Аналитика
  Одно событие на сборку, а не на каждую карту. Рядом с остальными в
  scrAnalytics — например analyticsAutoDeck(characterKey(character), placed),
  вызов в runAutoDeck.

9.5. «Дополнить», а не «пересобрать»
  Вторая кнопка или Shift+G: autoBuildDeck без цикла очистки и с пропуском
  занятых слотов (deckSlotRef(character, slot) != undefined -> continue).
  placedIds тогда стоит заранее заполнить уже лежащими картами, чтобы штраф
  за дубликаты учитывал их.

9.6. Собрать всех героев
  Сейчас не нужно (решение 0.1), но если понадобится: собирать по очереди
  по одному слоту (Лана слот 1, Вив слот 1, Лана слот 2...), иначе первый
  герой заберёт все лучшие карты. Для этого цикл по слотам выносится наружу,
  а внутри — цикл по героям.

9.7. Учитывать набор
  Решение 0.2 — без разницы. Если позже захочется «лесные карты — Фире»:
  в autoDeckScore + бонус, если cardSetById(cardId) == CardSet.Forest и
  character == Characters.Fox. Для этого character нужно передать в
  autoDeckScore (или положить в role).


================================================================================
  ЧАСТЬ 10. ПОРЯДОК, ЧЕК-ЛИСТ, ЧАСТЫЕ ОШИБКИ
================================================================================

Перед началом: правь .gml при закрытой IDE или потом сделай Reload — открытая
IDE затирает внешние правки. Новый скрипт scrAutoDeck создавай в IDE.

Порядок:
  1. Части 2–6 и проверка клавишей F8.
  2. Часть 7 — кнопка. F8 убрать.
  3. Часть 8 — подтверждение (8.2 сейчас, 8.1 после единого окна).
  4. Подбор весов (часть 5) на реальных коллекциях: новая игра, середина,
     после босса.

Чек-лист:
  [ ] Собирается колода только открытого героя; колоды остальных не меняются.
  [ ] Берутся только свободные копии; одна копия не оказывается в двух колодах.
  [ ] Фиксированные слоты спутника не тронуты.
  [ ] В колоде Ланы — магический урон и мана, у Вив — физический урон и
      лечение (если такие карты свободны).
  [ ] Повторное нажатие даёт другой, но тоже рабочий вариант (если есть из
      чего выбирать; в начале игры колода может повторяться — это нормально).
  [ ] Лана не берёт физические атаки, пока есть свободная магическая.
  [ ] Лесные карты могут попасть в колоду.
  [ ] Карт меньше, чем слотов — лишние слоты пустые, без ошибок.
  [ ] Пустая коллекция — ничего не падает, колода пустая.
  [ ] Пустая колода — сборка без вопроса; с картами — с подтверждением.
  [ ] После сборки панели обновились, данные сохранены (applyChanges).
  [ ] Во время обучения в декбилдере G ничего не делает.
  [ ] Подписи на русском и английском.

Частые ошибки:
  * Колода собрана «поверх» старой — забыта очистка в начале autoBuildDeck:
    старые карты держат копии, и freeCopies их не отдаёт.
  * Очищены и фиксированные слоты спутника — цикл очистки начинается с 0, а
    не с deckFixedSlots(character). setDeckSlot их всё равно не заполнит —
    останутся дыры.
  * freeCopies посчитан один раз до цикла — в колоду кладётся больше копий,
    чем есть. Проверяй на каждом слоте (setDeckSlot тогда вернёт false, а
    слот останется пустым).
  * Карты строятся через cardFromRef внутри цикла по слотам — медленно
    (6.1).
  * Лана собирает физические атаки — перепутан damageType в autoDeckRole или
    autoDeckDamageType смотрит не на тот эффект.
  * G срабатывает в окне подтверждения и открывает второе — нет общего стопа
    if (modalIsOpen()) { exit } в Step декбилдера (8.1).
  * Колоды всё время одинаковые — либо выбирать не из чего (мало свободных
    карт), либо полоса слишком узкая для разброса очков: смотри вывод из 9.1.
  * Лана иногда берёт физическую атаку при свободной магической —
    AUTO_DECK_SPREAD больше AUTO_DECK_ROLE_BONUS.
  * irandom(array_length(band)) без «- 1» — иногда выход за массив.
  * Числа весов прямо в autoDeckScore — собери в scrBalance, их придётся
    крутить.


Совет: не пытайся сделать автосборку умной. Шаблон + три веса уже дают
колоду, с которой можно пройти бой, а дальше игрок поправит руками. Если
захочется умнее — посмотри, как ИИ врагов оценивает ходы (scrEnemyAI:
estimateDamage, scoreMove): из этих оценок можно взять «силу» карты вместо
простого бонуса за редкость.
